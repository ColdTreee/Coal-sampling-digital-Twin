# 基于数字孪生技术的输煤取样系统开发文档

版本：0.2（工程规划稿）

日期：2026-11-19

依据：`docs/需求分析.docx`、`docs/0.附件2：辽宁工业大学大学生创新训练计划项目申请书.doc`

## 1. 文档目的

本文旨在将项目申请书中的研究目标和需求分析中的功能设想，转化为可分阶段高效落地的软件工程方案。首期聚焦构建数据链路闭环、可稳定运行的数字孪生系统原型，实现设备与流程可视化、批次和样品全链路追溯、规则告警及处置闭环；后续逐步拓展真实 PLC 接入、视频识别及企业级生产系统对接。

技术选型上采用主流 Web 单体架构：Vue 3 + TypeScript + Three.js 前端，FastAPI 后端，PostgreSQL 数据库，结合数据模拟器与 MQTT/HTTP 协议实现多源数据接入与业务验证。

## 2. 依据与需求解读

两份材料的共同目标是：以输煤取样过程为主线，关联来煤批次、采样任务、设备状态、样品流转和异常事件；建立设备、流程、样品的虚拟映射；提供监控、预警、追溯和管理功能。需求稿提出五层架构、边缘与中心协同、断网缓存和补传，以及按角色控制访问。申请书规划了调研设计、模型与基础开发、功能集成测试、优化总结四个实施阶段。

基于当前开发条件，明确首期实施边界与核心假设：

- **运行环境与控制边界**：首期主要面向 Web 端可视化与业务管理，通过只读模式接入数据，不向底层 PLC 下发控制指令。
- **数据源策略**：在接入真实工业现场数据前，构建高仿真数据模拟器与人工录入接口驱动业务链路，支持在界面灵活切换或标识“模拟运行”状态。
- **数字孪生定位**：首期重点实现设备运行状态、工艺流程的实时三维/二维映射及历史事件回放。
- **异常识别机制**：首期采用阈值判断、状态机与超时规则实现可解释的精准告警；后续在积累足量标注数据后，进一步引入机器学习算法进行预测性维护与智能分析。
- **行业标准对齐**：系统流程与数据字段设计充分参考国家及行业采样标准，具体业务阈值与工艺参数将在现场联调阶段由业务专家最终标定。

## 3. 目标与范围

### 3.1 首期目标

交付一套可一键本地或服务器部署的完整系统，支持创建或导入来煤批次，下发采样任务，实时接入设备与传感器数据，动态刷新三维孪生场景，触发精准异常告警并记录人工处置闭环，最终实现按批次查看完整事件链与导出追溯报告。

### 3.3 后续演进规划（二期及以后）

- **底层控制集成**：PLC 双向控制、设备联锁及安全保护联动。
- **AI 智能分析**：基于历史大数据的煤质预测、采样偏差自适应校正及设备剩余寿命（RUL）预测。
- **多模态感知**：视频 AI 行为识别、智能视频监控平台及门禁系统联动。

## 4. 技术方案比较与推荐

### 方案 A：Web 原型（推荐）

- **技术栈**：Vue 3 + TypeScript + Vite；Three.js；ECharts；FastAPI + Pydantic + SQLAlchemy；PostgreSQL；Mosquitto MQTT；Docker Compose；pytest 与 Playwright。
- **核心优势**：浏览器跨平台即开即用，无需安装客户端；Python 生态极其适合开发数据模拟器、规则引擎及后续的 AI 算法扩展；Three.js 能够流畅呈现 Web 端三维工艺流程；PostgreSQL 兼顾关系型业务数据与时序测点存储，架构简洁高效。
- **开发与维护**：架构轻量，工程效率高，无需在早期引入复杂的 Kubernetes 或独立时序数据库集群，适合快速迭代。
- **关注点**：需合理控制 Three.js 三维模型的面数与贴图复杂度，以保证 Web 端渲染流畅度。

### 方案 B：Java 企业后端

- **技术栈**：Vue 3 + TypeScript + Three.js；Spring Boot；PostgreSQL；MQTT Broker；Docker Compose。
- **核心优势**：企业级开发规范成熟，适合已有扎实 Java/Spring 技术积累、侧重复杂后台微服务演进的团队。
- **开发与维护**：工程样板代码较多，若后续引入 Python 数据分析与机器学习模型，需维护跨语言服务调用与部署。

### 方案 C：Unity 三维客户端

- **技术栈**：Unity；C# 服务端（ASP.NET Core）或独立 API；PostgreSQL；MQTT。
- **核心优势**：具备极强的三维渲染表现力与物理动画效果，适合对展厅级沉浸式视觉体验有极高要求的场景。
- **开发与维护**：需同时维护客户端安装包分发与 Web 后台管理系统，研发重心易向美术视觉倾斜，对硬件显卡有一定要求。

**综合推荐方案 A。** 该方案能以最优的研发效率和最低的运维复杂度，全面覆盖 Web 业务管理、高频事件处理与三维孪生可视化需求。团队也可结合成员实际技术栈优势进行微调。

## 5. 总体架构

系统采用模块化单体架构，按逻辑职责清晰分层。物理设备层通过模拟器或网关输出数据；接入层支持 HTTP/MQTT 双协议；后端核心负责数据校验、业务关联、规则计算与持久化；前端提供业务管理台与三维孪生大屏。

Plaintext

```
数据模拟器 / 人工录入 / 只读设备网关
                  |
          HTTP REST / MQTT
                  |
  FastAPI 接入与业务服务（校验、关联、告警、审计）
           |                      |
     PostgreSQL            WebSocket 实时推送
           |                      |
 Vue 业务管理台 + Three.js 孪生视图 + ECharts 趋势图
```

后端核心模块划分：

- `auth`：身份认证、RBAC 角色与接口权限控制。
- `master_data`：设备台账、传感器点位、告警规则及基础编码字典。
- `batches`：来煤批次、采样任务及样品全生命周期管理。
- `ingestion`：REST/MQTT 数据接入适配、格式校验、幂等去重及断网缓存补传接口。
- `events`：统一事件总线模型、时间线聚合与多维关联查询。
- `alarms`：实时规则引擎评估、告警状态机及处置闭环记录。
- `twin`：孪生场景实时状态聚合与历史轨迹回放引擎。
- `reports`：全链路追溯报告生成与 CSV 数据导出。
- `audit`：系统关键操作安全审计。

**数据流转机制**：数据源推送携带设备编号、采集时间戳和事件类型的报文；服务端完成校验后，依据幂等键去重并将测点与事件持久化，自动关联当前激活的采样任务；规则引擎实时评估状态并触发告警；通过 WebSocket 向前端推送状态变更通知，前端按需拉取详细视图数据。数据模型原生内置 `source_id`、`event_time`、`received_at` 和 `idempotency_key` 字段，平滑支持边缘端断网续传。

## 6. 关键数据设计

数据库统一采用关系型设计，主键使用 UUID，业务编号（批次号、样品号等）建立全局唯一索引。所有时间字段采用带时区时间戳，底层统一以 UTC 存储，前端按用户本地时区渲染。

| **实体**                   | **主要字段**                                                 | **说明**                                       |
| -------------------------- | ------------------------------------------------------------ | ---------------------------------------------- |
| `users` / `roles`          | 用户名、密码哈希、角色、启用状态                             | 采用加盐哈希加密存储密码，基于角色控制访问权限 |
| `devices`                  | 设备编号、名称、类型、位置、孪生对象键、状态                 | 物理台账与三维场景对象的核心映射表             |
| `sensor_points`            | 点位编号、设备编号、指标、单位、量程、阈值                   | 传感器配置及告警规则参数基准                   |
| `coal_batches`             | 批次编号、来源、运输方式、到达时间、状态                     | 业务追溯主线实体                               |
| `sampling_tasks`           | 任务编号、批次编号、计划/实际时间、状态、策略版本            | 记录采样任务执行全生命周期                     |
| `samples`                  | 样品编号、任务编号、样品类型、当前位置、封存状态             | 样品流转与交接主记录                           |
| `telemetry_points`         | 设备/点位编号、采集时间、接收时间、数值、质量标志、来源      | 高频传感器/模拟器时序测点数据                  |
| `events`                   | 事件类型、对象类型/编号、批次/任务/样品编号、时间、负载、幂等键 | 统一记录设备状态跃迁与人工操作事件             |
| `alarm_rules`              | 规则编号、条件、持续时间、级别、启用状态、版本               | 支持动态配置阈值与超时参数                     |
| `alarms` / `alarm_actions` | 告警来源、级别、状态、触发/确认/关闭时间、处置备注           | 支撑告警全生命周期闭环管理                     |
| `audit_logs`               | 操作者、动作、目标、时间、结果、变更摘要                     | 记录关键业务与配置变更，脱敏敏感信息           |

**数据一致性保障**：强制校验批次、任务、样品与设备编号的关联完整性；确保每个采样任务归属明确批次，每份样品可向上追溯至源头任务；所有关键状态跃迁自动沉淀为不可篡改的事件记录；严格执行幂等键去重；业务数据采用逻辑删除（作废/停用）并保留完整审计轨迹。

## 7. 接口约定

业务接口采用版本化 RESTful JSON API（`/api/v1`），所有写操作强制执行身份与权限校验，异常响应统一封装 `code`、`message` 与 `request_id` 便于排错。列表查询统一支持分页与多条件过滤。实时状态更新采用 WebSocket 推送轻量级变更通知，前端收到通知后异步拉取最新状态详情，实现高并发下的前后端状态同步。

核心接口清单：

- `POST /api/v1/batches`：新建来煤批次。
- `GET /api/v1/batches/{batch_id}/trace`：查询批次关联的任务、样品、事件及告警全链路追溯树。
- `POST /api/v1/sampling-tasks`：创建并下发采样任务。
- `POST /api/v1/ingestion/telemetry`：批量接收高频测点数据。
- `GET /api/v1/twin/state`：获取三维孪生场景当前全局聚合状态。
- `GET /api/v1/alarms`、`POST /api/v1/alarms/{alarm_id}/actions`：检索告警列表及提交人工处置动作。
- `GET /api/v1/reports/trace.csv`：按条件导出标准追溯报表。

**通信协议规范**：测点报文标准字段包含 `message_id`、`device_id`、`point_id`、`event_time`、`value`、`unit`、`quality` 和 `source`；事件报文统一包含 `event_id`、`event_type`、`occurred_at`、`device_id`、关联业务 ID（`batch_id`/`task_id`/`sample_id`）、`payload` 与 `idempotency_key`。MQTT 通信主题规划为 `coal-sampling/{site}/{device}/telemetry` 与 `coal-sampling/{site}/{device}/event`，生产环境部署强制开启账号认证、TLS 加密与 Topic 级 ACL 访问控制。

## 8. 规则与孪生建模

### 8.1 告警规则引擎

- **超阈值告警**：振动、电流或温湿度等关键指标超出设定阈值并持续指定时间窗口。
- **流程超时告警**：样品流转或采样任务在特定工艺节点滞留时间超出预期。
- **动作缺失告警**：任务处于执行中，但在规定观测窗口内未捕获到预期的设备动作事件。
- **状态逻辑冲突**：样品当前物理位置、设备运行状态与工艺流程节点出现逻辑不自洽。
- **数据质量异常**：捕获到未知设备/点位编码、时间戳异常超前或滞后、数值超出物理量程或重复报文。

每条告警均清晰呈现触发条件、关联实体、首次触发时间及标准排查指引，辅助值班人员快速定位并处置现场异常。

### 8.2 轻量级数字孪生建模

围绕采样头、给料/输送机、破碎机、缩分器、集样器等核心工艺设备，构建轻量化三维模型或规范化的 glTF 资产，通过唯一 `twin_object_key` 与数据库设备台账精准绑定。场景中的设备状态着色、物料流向动画、当前批次浮窗、告警闪烁标记及样品位置均由后端实时状态驱动。系统采用表现层与逻辑层解耦设计，支持在无 WebGL 硬件加速环境下自动降级为二维工艺流程图模式，保障全终端可用性。

## 9. 非功能要求与安全

系统设计严格对标工业软件工程规范，首期在标准测试数据集与本地/服务器环境下达成以下性能指标：

| **指标**         | **性能目标**                    | **验收基准**                        |
| ---------------- | ------------------------------- | ----------------------------------- |
| 主监控与常规查询 | 95% 请求响应时间 < 3 秒         | 标准测试数据集下的接口压测表现      |
| 批次全链路追溯   | 完整事件链查询 < 10 秒          | 单批次含完整采样与流转事件链        |
| 告警端到端延迟   | 规则触发后 < 5 秒内前端弹窗呈现 | 从测点入库到前端 WebSocket 渲染耗时 |
| 关键事件完整性   | 核心业务链路事件 100% 准确关联  | 自动化集成测试下无漏记、无重复入账  |
| 故障可恢复性     | 服务重启后业务数据零丢失        | 具备完善的数据库定时备份与恢复机制  |

**安全基线规范**：数据采集采用单向只读隔离架构，严格保护底层 PLC 控制网安全；全链路禁止明文存储密码与密钥，敏感配置通过环境变量注入；所有管理接口实施严格的服务端 RBAC 鉴权；MQTT 代理关闭匿名访问；关键参数变更、告警处置及数据导出全程留存不可篡改的审计日志。

## 10. 测试与验收

- **单元测试**：覆盖报文格式校验、幂等去重逻辑、任务与样品状态机跃迁、规则边界条件及权限拦截。
- **集成测试**：验证 FastAPI 与 PostgreSQL 的事务一致性、高并发批量测点写入及多表关联追溯查询。
- **端到端测试**：完整跑通“登录 -> 建批 -> 模拟运行 -> 触发告警 -> 人工处置 -> 追溯查询 -> 导出报表”全业务闭环。
- **孪生一致性测试**：验证三维场景设备着色与后端状态实时同步，测试 WebSocket 断线重连后的状态自动对齐，以及二维降级模式的可用性。
- **异常容错测试**：模拟非法编码注入、重复报文轰炸、乱序时间戳、数据库闪断、MQTT 断网重连及越权访问等极端场景。
- **交付物验收**：提交完整的部署手册、配置清单、数据字典、OpenAPI 接口文档、测试报告及标准化演示脚本。

系统内置三套一键可重置的标准化演示场景脚本：**正常采样全流程演练**、**设备异常阈值告警与处置闭环**、**样品流转超时及事件缺失追溯定位**，便于随时开展功能展示与教学答辩。

| 3-4      | 架构搭建与基础框架 | 前后端工程骨架、PostgreSQL 数据库迁移脚本、模拟数据协议、跑通端到端基础链路 |
| 5-7      | 核心业务模块研发   | 批次管理、采样任务、设备台账、样品流转、统一事件总线及追溯查询 API |
| 8-10     | 实时采集与数字孪生 | 数据模拟器、HTTP/MQTT 接入引擎、Three.js 三维场景渲染、ECharts 趋势图与历史回放 |
| 11-12    | 告警闭环与后台管理 | 规则引擎、告警处置流、RBAC 权限、操作审计、CSV 报表导出及三类演示场景联调 |
| 13-14    | 集成测试与性能优化 | 异常容错测试、端到端自动化测试、接口性能调优及缺陷清零       |
| 15-16    | 部署上线与结题验收 | Docker Compose 一键部署包、用户操作手册、技术白皮书及结题验收材料 |

研发过程严格遵循优先级驱动：**P0（批次/事件关联、全链路追溯、告警闭环）→ P1（三维孪生可视化、权限审计、报表导出）→ P2（真实硬件网关对接、AI 算法扩展）**。

## 12. 团队分工与协作

团队实行模块负责制与交叉代码审查（Code Review）机制，成员可根据特长兼任角色：

- **项目/需求负责人**：统筹研发进度、梳理采样业务流程、对接指导教师与验收标准。
- **前端开发负责人**：负责 Vue 3 业务管理台、状态管理、ECharts 数据可视化及前后端联调。
- **数字孪生负责人**：负责工艺设备建模、glTF 资产优化、Three.js 场景搭建与实时状态驱动。
- **后端/数据负责人**：负责 FastAPI 接口开发、数据库设计、事件模型、规则引擎与追溯算法。
- **测试/运维负责人**：负责数据模拟器开发、自动化测试套件编写、Docker Compose 编排与部署运维。

**工程协作规范**：采用 Git Flow 分支管理模型，所有功能合并必须通过 Pull Request 审查；接口契约与数据库变更先行评审；严禁将密钥、敏感凭证提交至代码仓库。

## 13. 仓库与交付建议

推荐采用清晰的 Monorepo 工程目录结构：

Plaintext

```
frontend/                 Vue 3 业务管理台与 Three.js 孪生视图
backend/app/              FastAPI 核心业务模块
backend/migrations/       Alembic 数据库版本迁移脚本
simulator/                高仿真输煤取样数据模拟器
infra/                    Docker Compose 与环境部署配置
tests/                    单元测试、集成测试与端到端测试套件
docs/                     需求文档、架构设计、接口规范、数据字典与部署手册
```

架构演进遵循“按需扩展”原则：首期通过 PostgreSQL 的分区表与复合索引高效承载时序测点数据，保持运维轻量；待后续接入大规模真实产线高频传感器后，再平滑引入 TimescaleDB/InfluxDB 时序数据库与 Redis 缓存集群。

## 14. 项目管理与前期对齐事项

为保障项目顺利推进并顺利通过结题验收，启动阶段需重点对齐以下事项：

1. **硬件与协议对接准备**：提前调研目标输煤系统的 PLC 型号与通信协议，在模拟联调成熟后，申请只读测试窗口开展真机数据对接。
2. **孪生视觉与业务重心平衡**：与指导教师确认验收侧重点，合理分配三维美术建模与后台业务追溯逻辑的开发工时。
3. **业务规则与阈值标定**：结合行业经验与指导教师建议，固化一套贴近真实工况的设备告警阈值与流程超时参数。
4. **国家/行业标准核对**：参照需求稿列出的 `GB/T 19494.1-2023`、`GB/T 19494.2-2023`、`GB/T 474-2008`、`GB/T 30730-2014`、`GB/T 30731-2014`、`GB/T 43219-2023` 等标准，在系统设计中规范采样流程与数据字段定义。
5. **项目申报材料一致性核查**：核对大创项目申请书中的团队成员名单（确保满足不少于 5 人的申报要求）以及预期成果（发明专利、软件著作权）与经费预算表的一致性。

## 15. 技术落地路径

1. **契约先行**：冻结 MVP 核心用例、状态机流转图与统一事件数据模型，构造标准追溯测试样例。
2. **数据底座**：搭建 PostgreSQL 数据库与 FastAPI 核心接口，率先跑通“批次—任务—样品—事件”全链路数据闭环。
3. **仿真驱动**：开发高仿真数据模拟器，持续注入正常、告警、断连、重复及乱序报文，验证规则引擎的准确性与幂等性。
4. **孪生赋能**：构建 Vue 业务台与 Three.js 轻量三维场景，通过统一事件时间线驱动设备状态实时渲染与历史回放。
5. **安全收口**：完善 RBAC 权限、操作审计、报表导出与异常处理机制，打包 Docker 一键部署环境，为后续对接真实工控设备做好准备。
