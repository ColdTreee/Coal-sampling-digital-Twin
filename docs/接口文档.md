# 接口文档

## 阶段一接口

### 健康检查

- 方法与路径：GET /health
- 用途：检查 API 进程和 PostgreSQL 连接是否正常。
- 成功响应：{"status":"ok","database":"ok"}
- 数据库不可用：HTTP 503，响应采用统一错误结构。
- 响应头：X-Request-ID，与错误响应中的 request_id 对应。

### 统一错误响应

错误响应包含 code、message 和 request_id。当前错误代码包括 http_error、validation_error 和 internal_error。生产日志不得包含密码、令牌或其他秘密。

## 数据库迁移

服务容器启动时执行 alembic upgrade head。本地运行可在 backend 目录安装 requirements.txt 后执行同一迁移命令。

OpenAPI 文档由 FastAPI 提供于 /docs 和 /openapi.json。

## 阶段二接口

- POST /api/v1/master-data/devices：登记设备。
- GET /api/v1/master-data/devices：分页查询启用设备。
- POST /api/v1/master-data/sensor-points：为现有设备登记测点。
- POST /api/v1/batches：创建来煤批次，并同步写入 batch.created 事件。
- GET /api/v1/batches：分页查询批次，可按状态筛选。
- POST /api/v1/sampling-tasks：为已存在批次创建任务，并同步写入 sampling_task.created 事件。
- POST /api/v1/samples：为已存在任务创建样品，并同步写入 sample.created 事件。
- GET /api/v1/batches/{batch_id}/trace：返回批次、任务、样品、事件、告警及缺失环节提示。
- POST /api/v1/master-data/alarm-rules：登记五种受支持类型的演示规则。
- POST /api/v1/ingestion/events：校验关联业务对象与事件时间，按 idempotency_key 去重并评估事件规则。
- POST /api/v1/ingestion/telemetry：接收单条测点报文或 messages 数组；按 message_id 去重，拒绝未知点位、单位不匹配和异常时间，并评估量程与阈值。
- GET /api/v1/alarms：支持分页和 status、severity 筛选。
- 告警列表字段包含触发条件、首次触发时间和建议核查动作。
- POST /api/v1/alarms/{alarm_id}/actions：执行 confirm、note 或 close。

## 演示场景

在安装后端依赖并启动 API 后，可运行 simulator/scenario_normal.py、simulator/scenario_threshold_alarm.py 或 simulator/scenario_timeout_trace.py。也可以使用 simulator/scenarios.py normal|threshold_alarm|timeout_trace。每次运行使用新的设备和业务编号，保留数据库中既有数据。

阶段二的写接口仍处于本地开发原型阶段，正式登录和角色权限在阶段五接入前不得部署到共享或生产环境。

## 阶段四与阶段五接口

- POST /api/v1/auth/login：OAuth2 表单登录，返回有效期一小时的 Bearer JWT。
- GET /api/v1/auth/me：返回当前启用账号与数据库中的角色。
- POST /api/v1/auth/users：仅管理员可以创建管理员、值班人员或只读账号，密码以 scrypt 哈希保存。
- GET /api/v1/twin/state：聚合当前批次、设备告警状态、样品位置及未关闭告警数。
- GET /api/v1/twin/trends?point_id=...：查询指定测点的分页趋势值。
- WS /api/v1/twin/updates?token=...：认证连接后仅推送 state_changed 通知，客户端应重新请求 REST 状态。
- GET /api/v1/audit/logs：管理员分页查询审计日志。
- GET /api/v1/reports/trace.csv：管理员或值班人员导出追溯 CSV，并生成审计记录。

角色分别为 administrator、operator、readonly。所有写操作均在服务端进行角色校验。演示脚本支持通过 --token 传入登录后的 Bearer JWT。
